# Curator 运行手册

本地内容管理台的启动、AI 配置、日常流程与安全边界。架构背景见 `docs/architecture.md`，内容契约见 `docs/data-model.md`。

## 启动

```bash
npm run curator           # 同时启动 curator-server(:4317) 和公开站 dev(:3000)
npm run curator:server    # 只启动服务
```

顶栏连接指示显示「服务正常 / 服务未启动」；未启动时页面仍可浏览，写操作会失败。首次冷启动会从 `data/tools.json` 引导生成 `.curator/content.sqlite`（已存在则直接用，绝不重复导入）。

## Agent 配置

收录和编辑器里的 AI 助手都通过 Vercel AI SDK 调用网关模型（`scripts/curator-ai.mjs`、`scripts/curator-workspace-agent.mjs`），整理规则在 `skills/curator-ingest/SKILL.md`。网关地址、API Key 和默认模型在 Curator「设置」页配置，只保存在项目忽略提交的 `.curator/pi-config.json` 中，不读取或修改电脑上的 Claude、Codex 与 CC Switch 配置。

- 界面只切换模型，不再启动 Codex 或 Claude Code CLI。
- Agent 仅拥有 `web_fetch`、`web_search`、`submit_draft` 三个工具；网页工具最多调用 4 次，草稿只能进入人工确认。

## 收录流程（`/curator/ingest/`）

1. 粘贴链接，可选指定目标板块（默认让 Agent 判断）。
2. Agent 按 `skills/curator-ingest/SKILL.md` 自行访问页面、对照目录、撰写草稿，进度实时显示。
3. 草稿就绪后人工核对：板块、双语文案（实时字数：verdict ≤16 字/8 词，summary ≤32 字/22 词）、定价、平台。
5. 保存：工具直接发布上线；技能/项目/提示词存为草稿，补正文后发布。
6. 「重新生成草稿」复用已抓取的页面只重跑 Agent，「重新分析」完全重来；分析面板可切换网关模型后重试。

来源无法抓取（如站点拒绝自动抓取）时，**重新处理**会降级用当前内容作依据继续走完流程；全新收录没有依据，会明确报错。

## 工作台（`/curator/`）

- **收录框**：粘贴一个或多个链接（一行一个）开始整理。已在资源库的链接会跳过并提示；只贴一条时直接进入它的工作区。整理排队进行，最多同时 2 条（`AGENT_CONCURRENCY`），避免一次打满模型网关。要粘贴正文或提示词，用完整收录页。
- **待处理**是一张清单，按资源去重，每条写明原因、只给一个动作：
  - 需要你确认：正在整理、整理完成、整理失败，或改了还没保存的工作区。
  - 没写完的草稿：状态为草稿的资源。
  - 已发布但不完整：公开目录里缺字段，或卡片文案会被截断的资源。
  原因来自服务端 `contentIssues()`（`scripts/curator-content-rules.mjs`），列表接口随每条返回 `issues` 代码。「卡片文案会被截断」按公开卡片两行能放下的量判断（中文 48 字 / 英文 30 词），比写作目标 `COPY_LIMITS` 宽，只标读者会看不全的。
- **公开站**：已公开条数、各板块数量，以及 `data/`、`content/`、`public/covers/`、`public/logos/` 里尚未提交的改动数（`GET /publish-status`，只读）。上线仍是手动提交并推送到 main。构建校验只显示状态，入口在系统页。
- **让 Agent 处理**：「没写完的草稿」和「已发布但不完整」各有一个批量按钮。缺封面的直接采集（不用模型）；缺分类、缺摘要、缺英文正文、卡片文案会被截断的，按原因写成具体指令交给工作区 Agent（`fixInstructions()`），最多同时 2 条。新标签这类需要人决定的会跳过。结果只是工作区里未保存的修改，出现在「需要你确认」，逐条检查后保存；已发布内容在保存前公开站不变。
- **整理**：打开资源就会建一个工作区；已保存、没有修改、7 天没动的会被列为可清理，旧收录流程留下的失败或未确认分析记录也在这里。只在点「清理旧记录」时执行，资源本身不受影响。

## 审核与发布

- 从工作台的任一待处理分组点进一条，就进入**审核模式**：顶部显示「分组 · 第 n / N 条」和这条会发布的改动（对比公开版本；没公开过的对比上次保存的版本），长文本可展开，封面直接显示缩略图，Agent 的修改提案标为「提案」。
- 主按钮「发布并下一条」：采用提案、保存、更新本地公开文件，然后打开同一分组的下一条；最后一条处理完回到工作台。「跳过」不保存直接看下一条。和公开版本没区别的，主按钮就是「下一条」。
- 不从工作台进入时，主按钮是「发布 / 发布更新」，「下一条」按资源库的顺序走。
- 编辑随时自动暂存，没有单独的保存按钮；「更多」里有「存为草稿（不公开）」、转换类型和归档。发布不再弹确认框：本地发布随时可改，推送后才上线。

## 编辑与候选（`/curator/resources/`）

- 列表负责查找：板块、检索、状态、排序、分页、「只看有问题的」（服务端统计缺失字段数）。
- 每条内容在独立编辑器里编辑，带未保存离开提醒和 revision 乐观锁（他人先保存会收到冲突提示）。
- 「AI 重新处理」抽屉：填处理要求 → 一行进度 → 预览改了哪些字段 → 「采用新版本」回到编辑器，保存后生效；放弃则不留任何痕迹。Agent 没产出结果时显示原因，可重试。
- 批量发布/归档在列表多选后操作。

## 系统页（`/curator/settings/`）

- **构建校验**：跑一次 `next build` 验证导出产物能否构建，实时日志；工作台只显示状态和失败入口。
- **AI 连接**：配置当前项目专用的网关地址、API Key 和模型；可从网关拉取模型，并用所选模型发起最小请求测试连接。上下文窗口、最大输出 Token、构建检查和清除连接在「高级」里。API Key 只显示尾号。
- **Agent**：显示项目连接是否可用及网关返回的模型列表。
- **运行记录**：本地 JSONL 任务记录统计（保留 30 份、14 天），可一键清除。

## 安全边界

- 服务只监听 `127.0.0.1`；CORS 白名单 = 本站来源 + `CURATOR_ALLOWED_ORIGIN`。
- AI 连接的密钥只写入忽略提交的 `.curator/pi-config.json`，权限为 `0600`；配置接口不返回明文密钥。
- 抓取前做 SSRF 校验：仅 http(s)、拒绝本机/内网/保留地址、每个重定向都重新校验；页面体积上限 2MB。
- Agent 工具结果不写入公开数据；草稿经过 schema 和字段规则校验后才可人工采用。
- 保存请求体上限 128KB；草稿字段逐项清洗与截断（`normalizeDraft`）。
- `.curator/` 与 `.env*` 都在 `.gitignore`；发布产物中不含 Curator 任何部分。

## 常见问题

| 现象 | 处理 |
|------|------|
| 页面提示「服务未启动」 | 先 `npm run curator`（或 `curator:server`） |
| 「站点拒绝自动抓取」 | 站点屏蔽了服务端抓取（如 openai.com）；收录换来源，重新处理会自动降级用现有内容 |
| 「这条资源已经存在」 | slug 或官网链接与目录重复，换 slug 或确认不是重复收录 |
| 「内容已在其他窗口更新」 | 另一个窗口先保存了，刷新编辑器后重做修改 |
| 保存后公开站没变化 | 工具需刷新；长文确认已发布（`active`）且有正文 |
