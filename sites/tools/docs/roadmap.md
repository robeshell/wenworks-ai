# 产品规划

日期：2026-09-28。状态：规划，未开始实施。配套：[架构](architecture.md) · [数据模型](data-model.md) · [工具收录计划](tools-collection-plan.md) · [Curator 工作区改版](curator-workflow-redesign.md)。

## 定位

一个人维护的、有立场的 AI 资源清单。每条都说清三件事：解决什么任务、相对同类差在哪、什么时候别用。

价值不在收得全，在于每条都有一句中英双语的 verdict——为什么它在这份清单上。对标的是 awesome-list 的反面：那些列表没有判断，这里只有判断。

所有功能从一个场景倒推：读者带着一个任务来，三十秒内知道选谁、为什么。

## 边界

静态导出 + 本地 Curator 决定了边界。下面这些明确不做，不因为容易做就加：

| 不做 | 原因 |
|------|------|
| 账号、收藏、评论、投稿 | 没有后端，也不需要。多人参与会稀释「一个人的判断」 |
| 服务端搜索、个性化推荐 | 客户端索引够用到几百条 |
| 多人协作编辑 | SQLite 在本机，这是特性不是缺陷 |
| Agent 自动发布 | Agent 只出草稿，人工保存。这条线现在守得好，继续守 |
| 评分、点赞、热门排序 | 需要后端，且会把判断让渡给流量 |
| `course` / `article` 板块 | 文章是另一种产品形态，会把清单拖成博客。清单过 100 条再议 |

## 公开站

### 改：入口从板块改成任务

现在首页按工具 / 技能 / 项目 / 站点 / 提示词分，这是编辑视角。读者想的是「我要做视频」「我要改代码」。

`data/taxonomy.json` 的 `categories` 已经是任务维度（coding、image、video、automation……），hint 也写得有判断力。让它升为一级导航，板块降为任务页里的分组或筛选。「编写代码」一页同时看到 Cursor、Claude Code、一个 skill、一个开源项目。

### 加

| 功能 | 说明 | 实现方式 |
|------|------|----------|
| verdict 前置 | 卡片视觉主角是那句「为什么在这里」，名字和 Logo 可以小 | 调整 `ResourceCard` / `ToolList` 层级 |
| 关键限制公开展示 | 收录计划要求每条写「一个决定是否使用的关键限制」，这是最诚实的部分，不该藏在详情里 | 新增 `caveat` 字段，见内容模型 |
| 同任务对比表 | 每个任务页底部一张小表：候选 × 适合谁 / 关键限制 / 定价 / 平台 | 构建时从 `caveat` 和 `alternatives` 生成，零运行时成本 |
| 核验日期 | 页面显示「2026-09-08 核验」，比「更新于」更可信 | 新增 `verifiedAt` 字段 |
| 更新流 + RSS | `/[locale]/changes/` 和 `feed.xml`，按时间排。归档也进流——下架一条比新增一条更能体现判断 | 构建时从 `updatedAt` / `archivedAt` 生成 |
| 客户端搜索 | 构建时生成 `search-index.json`（name、verdict、summary、tags 双语），前端模糊匹配 | 过 80 条再做 |

永久链接：本次改版已用 `data/route-aliases.json` 处理换板块后的旧地址，保持。

## Curator

22 条内容的瓶颈不是发现，是吞吐和新鲜度。工作区改版已把单条收录和编辑合并，不重做。在它之上加三样：

### 收件箱

`.curator/ingest-list.txt` 已经在被这样用，只是没有 UI。做成正式功能：

- 服务端 `POST /inbox` 收链接，工作台列出待处理项。
- 一个 bookmarklet 或 iOS 快捷指令，看到就丢进去。
- 「批量生成草稿」按钮，晚上一次跑完，第二天逐条审。

### 过期巡检

verdict 型清单最容易失信的地方：说「免费方案可用」，三个月后它收费了。

- 每条记 `verifiedAt`。
- 服务端提供 `POST /audit`：链接是否 200、GitHub 项目最近提交时间、定价页文案是否变化。
- 超过 90 天未核验的在工作台标黄，巡检发现异常的标红。

### 淘汰候选

收录计划里有「新增前先看能不能替换谁」，但没有工具支持。

- 收录时展示同任务下现有条目。
- 强制回答：它替换谁，或为什么并存。答案写进 `alternatives` 字段。

## 内容模型

所有新字段都必须 `{ en, zh }`，与现有一致。

| 字段 | 类型 | 说明 |
|------|------|------|
| `category` | 已有 | 升为一级维度，每条必填且只填一个主任务 |
| `caveat` | `Localized` | 关键限制，一句话。对比表和卡片都用 |
| `verifiedAt` | `string` (ISO date) | 最近一次核验日期，与 `updatedAt` 分开 |
| `alternatives` | `string[]` (slug) | 可替代的同任务条目 |
| `pairsWith` | `string[]` (slug) | 配合使用的条目，如 Claude Code + 某个 skill |
| `archivedReason` | `Localized` | 归档理由，进更新流 |

生命周期加一档：

```
draft → active → watching → archived
```

`watching`：已收录但有存疑（巡检异常、定价变动待确认），公开页面显示提示，不下架。

## 先后顺序

按当前体量和收益排：

| 序 | 事项 | 前提 | 侧 |
|----|------|------|-----|
| 1 | 收件箱 + 批量草稿 | 无。先解决收得慢 | Curator |
| 2 | `verifiedAt` + 过期巡检 | 无。保住可信度，越早越好 | Curator + 模型 |
| 3 | 首页改任务入口 + verdict 前置 + `caveat` | 内容到 40–50 条，否则任务页太空 | 公开站 + 模型 |
| 4 | 更新流 + RSS | 有稳定更新节奏 | 公开站 |
| 5 | 对比表 + `alternatives` / `pairsWith` | 同任务下有 3 个以上候选 | 公开站 + 模型 |
| 6 | 客户端搜索 | 过 80 条 | 公开站 |

2026-09-28 调整：公开站提前改成封面图卡片（`cover` 字段 + `npm run curator:covers`），不在上表中。原因是只有 logo 时版式怎么调都像占位，设计站的观感主要来自大图。

前两项只动 Curator，不影响公开站，可以在工作区改版提交后马上开始。
