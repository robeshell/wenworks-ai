日期：2026-09-08。状态：已按评审方案完成本地实施；验证记录见 [curator-workflow-validation.md](curator-workflow-validation.md)。范围：本地 Curator 的单条资源收录、维护、类型转换与 Agent 协作。

配套：[流程草图](curator-workflow-flows.md) · [可点击低保真草图](curator-workflow-sketch.html)。草图以示例数据演示交互，不调用 Agent、不读写真实资源。

## 设计结论

采用“资源工作区”：来源、内容、对话与修订围绕同一资源持续存在。新收录与编辑只是进入同一工作区的两种方式。类型可纠正；单字段修改就地完成；草稿尽早交付；保存有明确结束点。

第一版保留本地管理台、现有五类内容、Mantine 和 Git 静态发布模式。批量 Agent 编排、团队审核、自动部署、多 Agent 平台不进入本次范围。

本文前半部分保留当前问题与方案取舍，后半部分定义目标页面、状态、交互规则、数据边界与实施验收。前半部分的问题描述是改造前审计快照，保留用于说明决策背景；实施结果以验证记录为准。

## 目标

把一条资源从提交来源、形成草稿、多轮修改到保存的全过程放在同一个持续工作区。用户能纠正内容类型，能手动编辑，也能让 Agent 修改指定内容；保存完成后有明确结束点。

## 症结与代码证据

### 收录和编辑被拆成两份不同的任务

`components/CuratorStudio.tsx` 保存后直接 `router.push(curatorEditorHref(...))`。`ConversationPanel.tsx` 的收录结果是只读概览，文案却要求用户“检查并保存”，保存后还要去编辑器继续检查。

保存语义也不统一：`scripts/curator-server.mjs` 中工具、站点默认保存为 active，技能、项目、提示词默认保存为 draft。一个“保存到资源库”按钮产生不同状态，即使内容完整也不一定发布。

### 聊天外形下存在两种不同能力

收录阶段：`createConversationRun` 对未绑定资源的普通收录每次都从当前消息提取 URL；后续只发“摘要缩短一点”也会被要求提供链接。提示词模式则把当前消息作为新的提示词正文。生成路径没有接入历史消息和上一版草稿。

编辑阶段：`runCuratorConversation` 会带入历史文本，但只提供一个 `reorganize_resource` 工具，而且仅在当前消息命中特定“重新整理”表达时可用。系统规则明确排除“好的”“可以”“继续”，单字段编辑也没有对应工具。它因而可以聊天，却难以通过聊天完成渐进修改。

现有 Transitions.dev 对话恰好暴露这种矛盾：用户说“这个归站点 不是技能吧”，Agent 请用户确认后重写，但后续确认不满足工具开放规则。即使进入重新整理，服务端仍把目标板块固定为原来的技能。

此外，发送消息没有提交编辑器未保存的工作草稿；服务端读取的是已保存条目。用户手改后再让 AI 接着改，可能得到基于旧内容的建议。

### 等待包含多个串行阶段

| 方案 | 优点 | 代价 |

| 保留两页，补类型转换与完成提示 | 改动小，可以短期解除卡点 | 收录、编辑、对话仍是不同流程，需要继续维护状态交接 |

## 推荐流程

### 一个工作区贯穿资源生命周期

资源库负责检索、筛选和打开条目；“收录资源”创建新的资源工作区。工作台只聚合处理中、待检查和失败任务。

提交链接后保持原工作区与会话地址。第一版出来即显示可编辑内容。桌面端以正文、属性和预览为主区域，对话作为可调整宽度的辅助区域；窄窗口在“内容 / 对话”之间切换，避免长聊天把表单推到下面。内容类型、分类和保存状态保持容易找到。

首次保存之后仍停留原工作区，展示准确的“已保存草稿”，提供“继续收录”和“返回资源库”。更新公开版本后显示“公开内容已更新”；只有部署结果被验证后才能显示“线上已更新”。继续修改是可选操作。收录页与已有资源页可以保留不同入口，但底层使用同一工作区及草稿契约。

### 类型可以纠正，原内容可以找回

类型和类型内分类是两个独立字段。把技能改成站点时，保留资源身份、来源、对话和修订记录；兼容字段直接映射，目标类型必填项明确提示，不兼容字段保留在可恢复版本中。

类型转换不以删除重建实现。预览转换影响后一次应用到工作草稿，允许撤销；数据库事务写入版本与导出任务，文件导出作为可重试步骤执行，不能假设数据库与文件共享一个原子事务。公开版本更新时避免旧类型下残留条目，并处理旧链接。具体迁移见后文。

### 多轮对话有可执行结果

每轮都读取当前工作草稿、已有来源资料、历史消息和待确认操作。按意图分别回答问题、修改指定字段、转换类型、补充资料或全面重写。

“摘要短一点”只改摘要；“按站点整理”提出类型与关联字段变更；“好的，继续”承接上一轮明确提案。只有出现新的歧义或扩大影响范围时才澄清。

新增细粒度操作契约，例如修改字段、转换类型、补查来源。AI 修改进入工作草稿并显示改动和撤销入口。不同旧建议不能覆盖后续手动修改；应用时依据草稿版本检测冲突。

工作草稿自动保存在本地，刷新后恢复。正式保存或发布作用于明确版本。草稿已暂存、正在处理、已保存及已发布分别表达，避免用一个“完成”混在一起。

### 尽早交付可用草稿

调查达到足够证据后立即提供第一稿，先允许用户核对类型和方向。润色、翻译作为独立任务按需运行；未完成英文应明确显示，遵循现有公开内容规则。

短字段修改复用现有来源，不触发全量调查和翻译。用户可停止、补充要求、调整后继续；停止保留已生成内容和来源，不清空任务。

为首次反馈、首份可编辑草稿、单字段修改、完整整理分别记录耗时，再决定需要优化网络、模型还是步骤。后台结果带起始草稿版本，不能覆盖用户等待期间的修改。

## 验收场景

1. 提交链接后生成草稿，不保存就能手动改类型、分类、标题和摘要。
2. 连续输入“按站点整理”“摘要缩短”“保留这个标题”，在同一会话生效，无需反复贴链接。
3. Agent 提出明确修改，用户回复“好的”，能承接该提案。
4. 保存后有明确完成状态，继续收录直接开始下一条。
5. 已有技能转站点，保留内容身份、历史与可恢复字段，资源库及公开导出没有重复项。
6. 修改单个字段不重新联网抓取、润色全文或翻译全文。
7. 生成过程中手改内容，迟到的 AI 结果不会覆盖手改。
8. 刷新、停止、失败后仍可恢复草稿和上下文；没有来源链接的条目仍能讨论和编辑。

已观察真实入口、编辑器和分类控件；保存跳转与执行限制通过源码确认，耗时来自当前本地运行记录。没有再次运行模型、转换真实条目、保存或发布，也没有进行完整键盘、读屏、移动端或对比度审查。

## 信息架构与入口职责

| 入口 | 用户来这里做什么 | 页面内容 | 主要去向 |
| --- | --- | --- | --- |
| 工作台 | 接着做没有完成的事 | 正在处理、待检查、处理失败；每条显示资源名和具体下一步 | 恢复原工作区 |
| 资源库 | 找到并维护已收录内容 | 全部、各类型、草稿、已纳入公开目录、已归档；搜索与待补齐过滤 | 打开同一资源工作区 |
| 收录资源 | 开始一条新资源 | 链接或正文输入、可选类型、额外要求；提供直接手动编辑 | 新工作区 |
| 系统 | 设置模型、分类词表及服务 | 低频配置与维护 | 返回原位置 |

“收录资源”可同时作为资源库的主操作和导航快捷入口，但不能维护另一套编辑器。进入某类型下的新建入口时预选该类型，仍允许调整。第一版一条工作区处理一条资源；多链接输入时要求明确主资源，其余作为补充来源，不能静默批量创建。

未首次保存的工作区显示在工作台，不计入资源库总数。首次“保存草稿”才成为资源库条目；工作区 ID 与将来的资源 ID 稳定关联。保存之后不创建第二份会话。

## 关键页面与操作层级

### A. 收录入口

- 主输入：链接或待收录正文；类型默认为自动。选择提示词时明确“原文收录”，后续聊天不能替换原始提示词。
- 主操作“开始整理”，辅助操作“手动填写”。提交即持久化来源并进入工作区，不等待 AI 完成才显示页面。
- 精确 URL 查重尽早进行；发现已有条目时提供“打开已有资源”，不同收录对象允许明确选择“另建条目”。同域名只作提示，不作为重复判定。
- 网页抓取失败时保留链接，可补贴正文、重试读取或手动编辑。不要提供未经验证的伪草稿。

### B. 资源工作区

桌面结构：顶部返回入口、资源标题和状态；主区域为内容，右侧为 Agent；底部为当前草稿状态和保存操作。内容区域约占 60%–65%，对话约占 35%–40%，可拖动分隔线并收起对话。两侧独立滚动。

- 类型、分类、标题在内容顶部直接可见，避免收起关键纠错入口。
- 内容区提供“内容 / 预览 / 来源 / 历史”。中英文用切换或对照展示，避免两份长文强制纵向堆叠。
- 字段根据类型变化：工具展示定位、摘要、访问地址等；技能/项目展示双语正文；站点展示摘要、短详情、访问地址；提示词展示原文、变量和示例。
- Agent 的正文消息讲已完成什么和下一步；改动摘要显示具体字段并可展开差异。技术日志收在“处理详情”，不占据主对话。
- 用户直接要求的普通修改默认应用到工作草稿，并提供一次撤销；讨论和问答不修改内容。类型转换、整篇替换先展示影响，应用一次后即可继续编辑，不逐字段反复确认。
- 底部主操作随上下文变化，统一使用一个状态来源；运行状态显示在 Agent 区域，不覆盖“草稿已暂存”。

在 900px 以下改为“内容 / 对话”切换，保留标题、类型和保存入口。切换不丢输入、不重建会话；AI 完成后提示有新改动，不强制切换页面。恢复键盘焦点；处理完成消息使用温和的状态播报。

### C. 类型转换

由顶部类型选择器或 Agent 提案进入同一个影响预览。展示原类型、目标类型，以及“保留 / 需要调整 / 待补齐”三组内容。主操作“应用到草稿”，辅助操作“取消”。

普通转换不重复确认保存；类型转换应用后显示撤销入口。改变类型后，旧分类失效时标成待选择，不静默分配新分类。名称和 slug 不随类型自动改写；如需改名由独立修改指令决定。

### D. 保存完成

成功反馈直接出现在原工作区底部与完成条中，显示所保存的版本。首次保存后主操作“继续收录”，辅助操作“返回资源库”；编辑区继续可用。继续修改后完成条收起，恢复保存操作。

为已发布条目保存编辑草稿，不影响其公开版本；需要“更新公开内容”才提交公开版本变更。新条目需要“加入公开目录”。两种操作均需要发布校验，界面明示线上生效仍需项目原有 Git 发布流程。

## 保存、发布与运行状态

这是目标设计，区别于当前 `active` 条目保存后直接导出的行为。

| 维度 | 状态或含义 | 用户可见文案 |
| --- | --- | --- |
| 临时输入 | 尚未成功暂存 | 正在暂存 / 暂存失败，重试 |
| 工作草稿 | 自动持久化的可编辑版本，可不完整 | 草稿已暂存 |
| 正式草稿 | 点击保存后的明确版本，在资源库可找到 | 已保存草稿 |
| 公开版本 | 明确加入公开目录的快照，与工作草稿分离 | 已纳入公开目录 / 有未公开修改 |
| 导出 | 公开版本写入静态产物的任务 | 正在更新公开内容 / 公开内容已更新 / 导出失败，重试 |
| 线上部署 | 由现有 Git 工作流负责 | 未核验时不展示“线上已更新” |
| AI 运行 | 读取资料、整理、完成、停止、失败 | 位于 Agent 区域，独立于内容状态 |

“保存草稿”保存不完整内容；仅要求最小身份信息和安全的数据形状。“加入公开目录 / 更新公开内容”使用现有发布规则：所有类型需要有效分类和双语摘要；工具额外需要双语定位和有效访问地址；站点需要有效访问地址；技能和项目需要中文正文以及来源或相关链接；提示词需要正文。英文长文缺失为提示，不阻止发布；缺失双语摘要仍阻止发布。

本地暂存失败不能显示“已暂存”，离开前保留编辑缓冲并明确提醒。刷新可恢复以成功暂存为前提。归档影响公开目录，但不删除工作区或历史。

## 类型转换的数据映射

所有转换保留资源 ID、来源资料、会话、版本与首次创建时间。完整快照必须包含类型、分类、标题、slug 和 payload，不能仅保留正文。

| 转换范围 | 直接保留 | 需处理 |
| --- | --- | --- |
| 工具 ↔ 站点 | 名称、双语摘要、Logo、访问地址、兼容的短详情 | 转为工具需补定位；原类型特有字段进入保留区 |
| 技能 ↔ 项目 | 双语正文、摘要、相关链接 | 重新选择目标类型分类，复核标签与描述角度 |
| 技能/项目 → 工具/站点 | 名称、摘要、来源、可识别的访问地址 | 长文完整存入保留区；需短详情时显式提出改写，不截断正文冒充摘要 |
| 工具/站点 → 技能/项目 | 名称、摘要、来源及原字段 | 正文标为待补；允许基于已有证据补写 |
| 任意类型 → 提示词 | 通用元数据与来源 | 要求明确提示词原文，不把介绍文章自动当作指令正文 |
| 提示词 → 其他类型 | 通用元数据与来源 | 原提示词、变量、示例完整保留；不执行提示词 |

切回原类型可从最近完整快照恢复其字段，新的手工修改先做差异对比，不能整份覆盖。保存为转换后草稿不会删除旧公开版本。更新公开版本时才切换导出位置。

静态导出环境不能依赖服务端 301。第一版为有详情页的旧路径生成静态跳转页，包含明确的新地址与链接；转为没有详情页的工具时跳转到公开目录中可定位该资源的位置。两个语言版本分别处理，现有 slug 冲突需校验。页面别名的具体构建实现属于实施任务。

## Agent 多轮交互契约

| 用户表达 | 行为 | 结果与确认方式 |
| --- | --- | --- |
| “它是什么”“为什么分到技能” | 使用已有来源和当前内容回答 | 文本回复，不改草稿 |
| “摘要短一点” | 修改指定字段，复用已有资料 | 就地改草稿，显示差异与撤销 |
| “这个是站点，按站点整理” | 提出类型转换及关联内容改动 | 展示影响，应用到草稿 |
| “好的，继续” | 解析当前唯一、未过期的待执行提案 | 执行该提案；多个提案或版本变化时定向澄清 |
| “补查价格” | 针对缺失信息读取来源 | 给出来源及字段改动，不重写全文 |
| “全文重写” | 以当前资料和指令重写正文 | 预览整体差异后应用；不自动翻译 |
| “翻译成英文” | 翻译选定版本 | 只更新对应语言；期间中文变动则标为需复核 |
| “刚才那步撤销” | 撤销明确的最近一次 AI 改动 | 仅在没有后续冲突时直接逆向应用 |

每轮上下文包括当前草稿版本、完整资源属性、必要来源片段、对话摘要与近期消息、待执行提案。展示文本不能替代真实工具结果与结构化改动历史。

同一工作区只允许一个修改任务运行，避免两个 Agent 同时写草稿；不同资源可独立处理。运行时输入框保持可用，发送后可选“下一步处理”或“停止并按新要求继续”。前者进入可见队列，轮到时重新读取最新草稿；后者先确认原运行已停止，再以已保留资料和最新要求创建新运行。它不是从任意模型 token 精确续跑。

每个改动携带基准草稿版本和所改字段的旧值。用户等待期间只改了别的字段，可以合并；修改同一字段则展示冲突并让用户选保留当前或采用 AI。AI 失败不阻止手动编辑和保存。

## 性能与反馈设计

- 用户提交后立即显示消息与任务阶段；目标为本地 UI 在 300ms 内可见反馈，不承诺模型在该时间响应。
- 读取后尽快给出名称、类型、来源和首份可用内容。单个阶段完成即可更新，不等待整篇润色、翻译、Logo 全部完成。
- 第一稿是否可靠取决于来源证据；信息不足可以交付明确标缺的部分草稿，不能补造事实。
- 润色、翻译、补 Logo 为独立操作，可按需启动；后台结果不能覆盖较新草稿。
- 记录请求接受、首次可见回复、首份可编辑草稿、各工具耗时和完整结束时间。以同类任务和同一模型比较 P50/P95，实施后再确定模型与网络层优化。
- 一次网络失败可局部重试；阶段结果持久化后可继续，已完成部分不强制重跑。

## 持久化与服务边界（实施约束）

建议新增独立工作区及工作草稿记录，复用现有内容和会话基础，保持 SQLite 为编辑源。以下是契约层建议，具体表名与迁移编号由实施阶段核对。

| 对象 | 最小信息 | 责任 |
| --- | --- | --- |
| 资源工作区 | workspaceId、可选 resourceId、会话、来源、更新时间 | 新建至保存过程中保持身份稳定 |
| 工作草稿 | 完整内容快照、draftVersion、基准保存版本 | AI 与手动编辑共享；可不完整 |
| 内容修订 | 完整内容快照、来源操作、父版本 | 保存、类型转换和恢复有依据 |
| 公开版本引用 | resourceId、publishedRevisionId | 编辑草稿不改变公开内容 |
| Agent 操作 | requestId、runId、基准版本、状态、改动与来源 | 防重复请求，处理取消、冲突和恢复 |
| 导出任务 | 目标公开版本、状态、错误、重试信息 | 数据库与静态文件之间可恢复的一致性 |

数据库事务提交版本和导出任务；导出先生成临时产物，验证后替换目标，并记录完成。导出失败时内容保存结果仍成立，页面分别显示“草稿已保存 / 公开内容更新失败”。重试同一目标版本不得重复创建资源、修订或会话。

当前公开站只读取静态产物，继续保持这个边界。旧接口可暂时适配到新服务契约，不能让旧 `/runs/:id/save` 路径绕过新的草稿与公开版本分离。

## 迁移与实施顺序

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 1. 草稿与版本基础 | 工作区、自动暂存、草稿版本、公开快照分离；转换前完整快照 | 刷新恢复；编辑已公开条目不变更原公开产物；版本冲突可见 |
| 2. 统一页面 | 收录和编辑复用工作区；完成态；类型转换与撤销 | 新建到保存不换编辑器；技能转站点保留身份、字段和对话 |
| 3. Agent 协作 | 局部字段工具、上下文、待执行提案、排队及停止继续 | 多轮无需重复链接；可承接确认；不会覆盖手改 |
| 4. 早交付与导出恢复 | 首稿分阶段可编辑；独立润色翻译；静态别名与导出重试 | 首稿不被后处理阻塞；旧链接可到新内容；失败不会冒充成功 |

先迁移副本并验证，再处理真实库。保留已有 ID、slug、状态、标签、对话与修订；现有 active 条目初始化其公开版本引用。不要依赖短期 runs 日志重建唯一内容。旧编辑地址解析资源后进入稳定工作区地址，不因类型变化失效。

本次不执行迁移、模型调用、公开导出或提交发布。后续实现使用最小充分检查：核心状态和映射单元测试、保存与导出故障集成测试、真实页面验证，以及隔离测试资源上的真实 Provider 多轮验证；仅离线假模型通过不能代表 Agent 验收。

## 设计评审重点

本版采用以下默认值，供草图评审时调整：内容在左、对话在右；普通 AI 改动直接进入可撤销草稿；类型转换与全文替换先看影响；自动暂存与明确保存并存；公开版本独立更新；首稿之后按需润色、翻译。

评审先看能否完成任务，再调整视觉细节。重点走三条路径：一条新资源完整收录；把误判为技能的资源转成站点；手动改摘要后让 Agent 继续改且保留手动内容。
